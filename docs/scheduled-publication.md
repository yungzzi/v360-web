# 半小时批次发布

启用后按设备目录开始时间加报告时长计算结束时间，将结束时间落在
[12:00,12:30)的录像归入该批次，13:00发布；[12:30,13:00)于13:30发布。
跨日同理，片段不切割。目录时长仅为设备报告值，目录异常仍保留提示。
下载和网页准备提前进行，发布时展示已成功部分；缺口不阻塞整批。

每段最多5次自动尝试，失败机会按约1、3、8、15分钟间隔分散；到发布时间
不再开始该段的自动工作。一次设备连接失败只触发设备级恢复，不消耗
该段取文件名额。停止后待转换队列释放槽位，避免旧失败阻塞新录像。
失败次数独立存储，重启保留。手动重试每次只执行一次下载及网页准备，
不清空自动历史；成功则补入原批次，尚未到发布时间的仍等待发布。

数据库publication_settings控制功能开关，默认关闭以兼容旧部署；升级
确认就绪后通过受认证PUT /api/publication?enabled=true启用。
GET /api/publication?day=YYYY-MM-DD提供批次与停止清单；
POST /api/jobs/retry-once/{id}共用摄像头任务锁。时间轴和媒体接口执行
发布限制，录像管理列表保留准备进度。前端每30秒刷新发布状态，提供
选中项顺序重试。原片及网页版本仍受15GiB合计预算和播放保护约束。

本次不宣称解决摄像头拒绝下载，也不把停止条目移出已知缺口统计。
