# 实时声音

实时观看新增“开启声音 / 静音”。每次开始默认静音，收到可用声音后按钮可用；停止、退出或最后一个观看者离开时同时结束画面和声音。不请求浏览器麦克风，不包含双向对讲。

协议来自同一份 V360 Pro 7.2.0 APK：REA 确认 P2pSDK.startLiveAudio/stopLiveAudio 分别调用 IOCTRL_AUDIO；直接读取 DEX 静态字段确认命令 4/5，参数为主镜头索引的四字节小端值。Live 音视频共用已有连接的通道 2，音频标志 428216306，codec=82 对应 G711A。真实短时采样约每秒 25 个 320 字节包，对应 8kHz 单声道。原始反编译证据与声音片段仅保存在私有分析目录，不入 Git。

后端先短暂等待声音，缺失或格式不支持时回退到视频；支持后使用同一 FFmpeg 输出包含 H.264 和 AAC 的分片 MP4，由同一个浏览器播放器同步播放。输入视频队列 32 项、音频队列 64 项，写入超时 5 秒；初始化等待声音最多约 2 秒或 4 MiB 视频。音频小范围缺包补静音，严重中断结束该次观看并释放连接，用户可重新连接。没有新增长期直播录像任务；已有 SD 保存和回放行为保留。

软件验证包含音频请求/结束、分流、缺失/不支持时保留视频、小范围缺包、大范围中断、实际 FFmpeg 双轨输出及解码、后加入共享连接和启动失败时管道/摄像头锁清理。136 项原有及新增检查通过，补充资源清理检查后为 137 项。

真实本地网页短时测试：同一个摄像头会话收到 700 个视频包、1150 个音频包、输出 45 个分片；Edge 正常播放并切换静音。私有检查片段视频 12.064063 秒、音频 12.096 秒，时间轴长度差约 32ms；两条轨道可独立解码，声音为非零信号。停止后 state=stopped、viewers=0、error=null。这不能证明长时间同步、声音清晰度或真实手机兼容性，实际听感仍需用户验收。
