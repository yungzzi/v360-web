# 本地网页持续直播

已实现本地网页访问认证、持续播放、开始/停止、全屏和状态显示。网页访问令牌仅保留在当前页内存，不进入浏览器存储或视频 URL；当前采用单用户共享令牌，尚非多用户账户系统。网页资源全部本地提供，没有第三方播放器 CDN。

## 启动

```bash
cd /home/yungzzi/workspace/04_tools-and-scripts/v360-web
uv sync --extra dev --locked
uv run v360 serve --port 8080
```

Windows 浏览器访问 `http://127.0.0.1:8080`。网页令牌在 `.private/web.json` 的 `access_token` 中，只在本机查看并输入页面，不发送到聊天。无需手机或 USB 调试。只监听回环地址，没有部署公网服务。

## 结构与约束

摄像头 → native-arm64 客户端 → 单个 FFmpeg → H.264 分片 MP4 → 已认证 WebSocket → 浏览器 MSE。

- 请求主子通道、HEVC、已验证的 640×360 档位，时间轴暂按该设备的 15 fps 构造，仅视频。输出目标码率 384 kbit/s、上限 512 kbit/s，限制解码、编码和滤镜线程。
- 最多三个观看连接共享一个摄像头会话和一条转码流水线。新观看者先取得初始化信息，再从下一个关键帧分片加入。
- 服务端每个队列最多四项，单个分片最多 2 MiB，慢客户端被断开。浏览器限制待追加队列并清理旧播放缓冲。
- 最后一个观看者退出时停止输入、请求摄像头停止、关闭 SDK 会话和回收 FFmpeg；SDK 操作仍可能等到其超时，不能保证异常情况下瞬时释放。每次观看最多 30 分钟，结束可重新连接。
- 直播只在内存传输，不自动保存直播录像，不生成不断增长的磁盘缓存。摄像头锁与现有 SD 任务共用，观看期间其他摄像头任务返回忙。云台后续需接入活动连接。
- 仅支持单应用进程；多进程会拥有不同的锁和转码器，当前不得这样部署。
- 队列及并发限制已实现。CPU/内存资源组硬限额、10 GiB 归档及保留期清理尚待部署和存储功能实现，单线程不等于 CPU 硬配额。

## 验收

先用原片段回放验证浏览器播放器，再切换真实摄像头。Edge 实际持续解码为 640×360，两个窗口均能播放，后加入者时间轴也正常推进。真实会话结束时收取 1,222 帧，输出 81 个分片；这是约一分钟以上的短时实验，不是长时间稳定性验收。

双窗口期间进程树只有 Python、一个 QEMU 和一个 FFmpeg；首窗口退出后另一窗口继续播放。最后退出后 state=stopped、viewers=0、error=null，应用没有剩余直接子进程。本次未单独记录原生 ForceClose/DeInitialize 返回码。

本机 WSL 单观看者四秒采样：Python RSS 56.1 MiB、QEMU 19.4 MiB、FFmpeg 66.1 MiB，合计约 141.5 MiB（共享页可能重复计数），CPU 约单核 7.5%。这不是峰值、cgroup 内存统计或阿里云性能承诺。

当前全部 72 项软件检查通过，覆盖真实 FFmpeg 分片及独立解码、共享流水线、断开清理、慢客户端、非法大分片、认证/Origin 拒绝、静态资源边界和转码器启动失败。wheel 构建通过。HTTP/WebSocket 也经本机 wsproto 实际运行，非仅进程内 TestClient。原始摄像头截图仅在本地交付目录，不入 Git。

公网 HTTPS、反代 WebSocket、移动浏览器、长时间断线恢复、PTZ、独立深睡唤醒和阿里云仍待验收。结果摘要见 [脱敏验收](evidence/browser-live-validation.json)。实现参考 [FFmpeg 官方分片文档](https://ffmpeg.org/ffmpeg-formats.html) 和 [Starlette WebSocket 文档](https://starlette.dev/websockets/)。

退出竞态修复：已经断开的 WebSocket 再次关闭不会作为应用错误；ASGI 取消时先同步解除观看者归属，再等待异步收尾，避免清理被取消后保留连接。新增回归后全套 72 项通过，两个退出用例连续重复五轮均通过；实际 wsproto 回放流连接退出后的 traceback 数为 0。
