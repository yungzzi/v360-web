# 三画面切换

实时页面增加“主镜头 / 镜头二 / 镜头三”选择。正在观看时切换会先释放旧连接再连接所选画面，停止状态下只切换选项，不唤醒设备。主镜头保留声音、方向控制及 SD 录像功能，其他两个只提供画面；历史列表、后台自动保存和下载仍只处理主镜头。

此摄像头的账号设备类型为 29，原 App 将其映射到 FakeThree，采用两路视频形成三个显示窗口。主画面来自 PPCS 通道 2，附加两幅画面来自通道 5。第三窗口不是额外请求通道 6；真实取样确认 2/5 有数据，而 6 无数据。原 App DeviceUtil.renderMode 与 ThreeLiveFragment.initLiveView 分别给两个附加窗口设置模式 1/2。原生 libccq_media 的 screenshot::getRenderRegion 和 getTextureCoordinates 中，模式 1 为 [0,.2,.6,.8]，模式 2 为 [.4,.2,1,.8]。后端按同样区域处理已验证的 640×360 源，再输出 640×360；这两个区域有重叠，不是简单左右对半分。只记录协议与区域事实，不将第三方二进制或反编译全文放入 Git。

此布局须在私有 device.json 的 channels 中显式设置 `"layout": "dual-three"`。默认 `single`，不自动将其他设备套用该模式。该配置只改变自建客户端，不改变摄像头设置。

保持单个摄像头连接和单个转码器。最多三个同镜头观看窗口共享它；已有窗口观看其他镜头时，新请求返回明确冲突提示，不强制切换别人。旧会话停止期间新请求有限等待，超时提示重试；不能在这台服务器上并行开启三个转码器。附加窗口的方向控制在后端也被拒绝。

软件检查为 148 项通过，覆盖显式布局、非法镜头拒绝、合成色块确认取景区域、附加通道读取且不请求声音、同镜头共享、不同镜头冲突和退出后切换。Edge 真实摄像头完成主→二→三连续切换，各自正常播放 640×360；每个画面的检查片段可解码，主画面含声音，其他两个仅视频。第二窗口请求不同镜头显示冲突提示，原窗口继续播放。测试后 viewers=0、state=stopped、error=null，并已恢复云端自动保存。真实手机及长时间切换稳定性尚待验收。
