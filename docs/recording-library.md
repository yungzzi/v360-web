# 历史录像与回放

登录后选择“历史录像”，按设备本地日期查看。默认时间轴展示已准备好、已发布的录像；可切换到所有已知目录项。拖动蓝线，松手后回放：落在录像内时保留所选位置，落在空白处时只向后吸附，不跳回之前的录像。也可使用上一段、下一段。

## 文件从哪里来

- 已准备好的录像直接读取服务器文件，不再次访问摄像头。
- 只有原片时，需要生成网页版本；服务器档会提前做这一步。
- 只有目录记录时，需要先下载，耗时取决于设备可达性及处理队列。

按日期的目录读取不会主动唤醒摄像头；“从摄像头更新目录”才请求设备。目录异常、未发现范围和停止处理项仍保留提示。空白不证明摄像头从未录像；“已发现”不等于“可回放”。自动规则见 [自动保存](automatic-archive.md) 和 [批次发布](scheduled-publication.md)。

切换日期或刷新页面可复用有时效的目录缓存，选中已就绪片段不必等待整份目录重新加载。缓存只含元数据，不保存密码和视频，退出时清除；媒体读取仍执行鉴权和发布限制。实现与历史测量见 [回放性能](history-performance.md)。

## 管理操作

日常只需日期、播放器和时间轴。“管理与诊断”收纳同步状态、失败清单、手动补取和存储设置；文件管理支持下载原片及锁定保留。保存当前画面会下载 JPEG 到访问设备，不在服务器增加一份截图。

后台自动下载和网页准备不需要逐段点击。超过自动次数或发布时间的片段可手动重试一次；失败不会标成成功，也不会清空原有尝试记录。刷新页面保留持久任务记录，服务重启中断的工作按可恢复状态处理，不把部分文件当作成品。

主镜头回放保留可用音轨，两个附加画面仅直播。当前不支持对讲、附加镜头归档或全天连续录像。

## 容量与访问保护

服务器档将原片、网页文件及直播缓存计入同一个 15 GiB 预算，保留 8 GiB 文件系统余量；锁定与播放中的文件受保护。实际保留天数取决于录像量，见 [资源预算](resource-budget.md)。

浏览器使用独立登录 Cookie 访问列表、媒体和操作接口，维护客户端可继续使用 API Bearer 令牌。视频 URL 不包含主令牌，已准备文件也不能绕过身份或发布时间检查。下载支持 Range 请求；文件需通过来源、大小及路径边界检查。登录细节见 [访问密码](browser-password.md)。

本项目已完成真实片段及云端网页回放，但未证明设备目录完整、所有旧片可取或长期零遗漏。早期验证样本见 [历史验收记录](evidence/recording-library-validation.json)。
