# 从正常账号导入设备参数

适用于本项目已分析的 V360 Pro 7.2.0 APK。用户无需知道单独的设备密码：原 App 在账号登录后取得设备列表，再用包内的账号参数加密配置解码设备 DID 和设备密码。命令用户标识来自登录结果的 `id`。

## 本机准备

开发者先从用户提供的原 APK 导入本地账号配置；该文件包含厂商 SDK 参数，放在 `.private/` 并排除 Git。不会重复写入 PPCS SDK 文件：

```bash
uv run v360 import-cloud-apk /path/to/the/analyzed.apk
```

目标 DID 必须已保存在 `.private/device.json`。导入只匹配该 DID；没有匹配或存在多个匹配都会停止，保留原配置。

设备列表的原始 JSON 字段由原 App 的 Gson 注解映射：`uid` 对应内部 `did`，`isShareDevice` 对应内部 `isSharedDev`。2026-10-29 已用真实账号缓存验证：返回 1 台设备，解码并唯一匹配已保存 DID，设备参数成功导入，随后摄像头登录认证通过。原始 JSON 和凭据仍只保存在本地私有目录。

## 用户仅需输入一次账号密码

在 WSL 终端运行：

```bash
cd ~/src/v360-web  # 替换为实际克隆目录
uv run v360 cloud-login
```

依次输入原 App 的手机号或邮箱、账号登录密码。密码输入不显示字符，属于正常现象。不要把密码作为命令参数，也不要发到聊天里。

命令通过 HTTPS 向包内的厂商账号接口登录，然后请求账号设备列表。账号密码只用于本次请求，不写入配置、日志或命令参数。登录成功即把账号令牌、用户标识和独立客户端 UUID 写入 `.private/cloud-session.json`，后续设备匹配失败也保留此会话。原始设备列表仅缓存到 `.private/cloud-devices.json`，不在终端输出；设备密码导入本地私有设备配置。上述文件使用 600 权限，排除 Git。已有手机桥接令牌和连接模式保持不变。

成功时输出 `device_credentials_imported: true`。此命令不会登录摄像头、开始视频、修改设备设置或部署服务器。若服务要求验证码或返回不兼容结构，命令停止；不要反复重试。

## 登录成功但设备未匹配

错误会输出收到的设备数、成功解码的 DID 数和匹配数；脱敏计数同时写入 `.private/cloud-import-diagnostic.json`。这些计数用于区分空列表、字段解码失败和设备身份不符，不能单凭 `cloud_target` 断言是哪一种原因。不会自动选择另一台设备，也不会覆盖现有设备配置。

开发者可在诊断后复用已保存会话，无需再次输入密码：

```bash
uv run v360 cloud-import
# 仅重新处理已有私有列表，不访问厂商接口
uv run v360 cloud-import --cached
```

厂商会话失效时才需再次 `cloud-login`。旧版工具在设备匹配成功后才保存会话；使用旧版产生的失败没有可恢复的令牌，需要在此修正后重新登录一次。不要把令牌、完整设备列表或私有配置发到聊天里。

## 后续验证

开发者继续执行短时 `connect-check`，检查返回后会话数回到 0，再读取 SD 列表及一个片段。真实账号接口接受本客户端的情况，必须由实际登录结果确认；模拟接口检查不能替代账号验收。
