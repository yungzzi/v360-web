日期：2026-10-29。开发分支：`feat/ppcs-recording-bootstrap`。

## 已执行的软件检查

- Python TCP 集成检查：认证、碎片化 RPC、PPCS 部分读取、分页列表、下载大小/序号/结束标记、超时和连接释放。
- 实际运行项目局部 FFmpeg 生成合成测试视频，再经 TCP 测试对端传输，核对字节并独立探测和解码。
- API 鉴权覆盖目录和媒体；未验证录像或越出数据根目录的路径不会被提供。
- SQLite 重复发现保持单一索引及已有验证状态。
- WSL → Windows Python → Windows 回环测试对端实际收发成功。测试对端没有连接摄像头。
- Android Java 编译、D8 转换、APK 签名验证及 ZIP 对齐检查。
- 普通 JDK 检查一次性配对窗口的到期、重放及尝试次数。
- 临时 Git 仓库检查 main 普通提交被阻止，功能分支可提交，`--no-ff` 合并产生双父提交。

Python 当前共 21 项检查通过，最终记录见 `docs/evidence/software-validation.json`。测试适配器目前有一个 Starlette/httpx 弃用提示，检查本身通过。

## 当前运行约束

- 配置的通道及连接模式可调整；当前命令通道 0、下载通道 4 来自静态证据，用户硬件兼容尚未验证。
- 下载若缺少开始/结束标记、长度不符或包序号不连续，会保留未完成文件而不标为可播放成品。
- SDK 文件可能仍包含厂商私有媒体结构；识别/解码失败时保留为“已下载未验证”，不会假定是 MP4。
- `recTime` 单位与设备时区尚未实际核对，因此索引保留原始时长值和设备本地日期。
- SDK 原生连接调用的内部超时尚未测量；主程序有桥接超时，手机停止时会请求中断并保留清理责任，不能保证立即终止失去响应的原生调用。
- API 任务目前只在内存记录，重启不自动恢复；初版仅支持单进程服务和串行摄像头任务。
- 用户的全天连续录像目标仍需确认设备 SD 工作模式，事件片段不能替代全天时间覆盖。

当前功能分支保留提交，不合并 main，等待最小真机闭环完成。
