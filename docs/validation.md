- SQLite 重复发现保持单一索引及已有验证状态。
- WSL → Windows Python → Windows 回环测试对端实际收发成功。测试对端没有连接摄像头。
- Android Java 编译、D8 转换、APK 签名验证及 ZIP 对齐检查。
- 普通 JDK 检查一次性配对窗口的到期、重放及尝试次数。
- 临时 Git 仓库检查 main 普通提交被阻止，功能分支可提交，`--no-ff` 合并产生双父提交。

初始 21 项检查记录见 `docs/evidence/software-validation.json`；当前新增账号导入、SD 兼容和原生进程适配检查后共 47 项通过。测试适配器目前有一个 Starlette/httpx 弃用提示，检查本身通过。

## 已执行的真实设备检查

2026-10-29，已授权手机 RMX3700 安装助手，USB 配对与 WSL `bridge-check` 成功，SDK API 版本返回 `84017664`。原 App 报告版本 7.2.0（706）。

已从原 App 设置页取得目标设备 DID 并仅保存到本地私有配置。原包 `DeviceUtil.getConnectMode` 的 LTE 分支返回 94；用该模式和对应 BFEP SDK 服务器参数，真实 PPCS 连接一次成功，连接与关闭合计约 2.97 秒。助手关闭 RPC 返回 0，再次检查会话数为 0；此版未单独记录原生 ForceClose 的返回码。SDK 初始化返回 0。此步骤未发送设备登录、视频或设备设置命令。

原 App 在测试前访问过设备设置，因此本次不能确认深睡后的独立唤醒。一次连接也不能证明持续稳定性。脱敏记录见 `docs/evidence/android-device-validation.json`；DID、账号、密码、令牌及截图均不进入 Git。

## 正常账号参数导入的软件检查

分支 `feat/cloud-device-onboarding` 增加 `cloud-login`，通过原包 HTTPS 登录和设备列表接口，仅导入与已保存 DID 唯一匹配的设备参数。账号密码不持久化；手机桥令牌及当前连接模式保留。

原包 `AesUtil` 调用 native `AesC`；ARM64 `libopenssl.so` 的导出函数、OpenSSL 导入和反汇编确认 AES-128-ECB 与默认 EVP 填充流程，JNI 直接使用传入的 UTF-8 key。四组加密结果与另行执行的 JDK 17 Cipher(AES/ECB/PKCS5Padding) 向量一致，包含中文、整块和较长输入。

真实账号返回的 JSON 通过 Gson 注解映射：`uid` 对应 `did`，`isShareDevice` 对应 `isSharedDev`。已修正此前直接使用内部字段名的问题。真实账号列表返回 1 台设备，解码后与已保存 DID 唯一匹配，设备凭据成功导入，摄像头登录认证通过。

## 真实 SD 目录、下载和本地 API

初次保留的目录响应声明 91 条记录，其中首条日期无效、90 条日期有效，并有一个额外的 12 字节尾部槽位。原 App 构造函数按 count 读取，不能把尾部字节当作额外录像。异常首条的生产端原因尚未确定。

默认仍严格拒绝无效日期。已对这台设备的私有配置显式启用 `allow_invalid_record_dates`，只索引有效条目、保留原始异常响应并返回不完整标志。最新真实命令查询取得 95 条有效记录，另有 1 条异常记录，`metadata_complete: false`；数量随新事件发生变化。

已从真实 SD 记录选择一个原始时长值为 15 的片段，经 PPCS 下载 1,298,591 字节，校验声明长度、包序和结束标志，FFprobe 识别为 MP4/MOV 系列容器，视频 HEVC、音频 PCM A-law。FFmpeg 整段解码通过。另生成 H.264/AAC 兼容播放版，探测时长 15.061 秒，整段解码亦通过；不据此把所有设备的原始时长字段一概认定为秒。

用户随后反馈，交付片段的画面符合家中摄像头场景预期；这补充了单片段人工画面对照，不等同于完整目录、全天录像或长期运行验收。

使用真实下载文件验证 FastAPI：未认证访问 401，认证访问 200，内容 SHA-256 与下载记录一致，Range 请求 206，未验证条目 404。此检查使用进程内 TestClient，没有部署公网服务或验证完整网页。最后 `bridge-check` 返回 active_sessions 为 0；原生 ForceClose 返回码仍未单独记录。

脱敏验收摘要见 `docs/evidence/sd-camera-validation.json`。SDK 连接错误 -3 仅对底层连接重试一次，摄像头密码认证拒绝不重试。手机桥曾出现无响应并由重启助手恢复，尚不能宣称长期稳定。

## 无手机路径的后续验收

已停用项目手机助手并移除其 USB 转发，使用无手机桥令牌、无 Windows Python 配置的 `native-arm64` 适配器完成设备认证。服务层真实查询返回 101 条有效记录和 1 条异常日期记录，并保留 `metadata_complete: false`。随后通过正常下载服务取得另一个 1,452,034 字节的片段，完整解码通过，兼容版时长 15.060 秒。FastAPI 访问真实文件的 401/200、内容 hash 和适配器状态检查通过。

初始化、目录及认证检查后，原生工作进程的 ForceClose 和 DeInitialize 返回 0，进程已退出；异常帧和阻塞进程的终止另由合成子进程检查覆盖。默认本机配置已切换为 `native-arm64`，无需连接手机或运行 ADB。来源、范围及限制见 `docs/native-backend.md` 和 `docs/evidence/native-worker-validation.json`。

原 V360 Pro 的后台状态未隔离，因此深睡首次唤醒仍未独立验收；阿里云运行和长期稳定性也未验收。本机完成取片不自动代表这些条件成立。

## 当前运行约束

- 此设备已验证命令通道 0、下载通道 4、录像通道 0 和 LTE 连接模式 94。其他型号和通道尚未验收；通用模板保留原默认连接模式。
- 下载若缺少开始/结束标记、长度不符或包序号不连续，会保留未完成文件而不标为可播放成品。
- 本次文件可独立识别及解码；其他片段若识别/解码失败仍保留为“已下载未验证”，不假定所有文件均为同一格式。
- `recTime` 单位与设备时区尚未实际核对，因此索引保留原始时长值和设备本地日期。
- SDK 原生连接调用的内部超时尚未测量；主程序有桥接超时，手机停止时会请求中断并保留清理责任，不能保证立即终止失去响应的原生调用。
- API 任务目前只在内存记录，重启不自动恢复；初版仅支持单进程服务和串行摄像头任务。
- 用户已确认原设备不支持全天连续录像，取消该验收要求；目标为保存设备实际生成的观看期间和动作触发片段，继续核对这些片段的同步完整性。

最小真实 SD 片段闭环已完成。开发汇总分支继续保留，完整网页、直播、云台及长期运行仍未验收。
