## 已执行的真实设备检查

2026-10-29，已授权手机 RMX3700 安装助手，USB 配对与 WSL `bridge-check` 成功，SDK API 版本返回 `84017664`。原 App 报告版本 7.2.0（706）。

已从原 App 设置页取得目标设备 DID 并仅保存到本地私有配置。原包 `DeviceUtil.getConnectMode` 的 LTE 分支返回 94；用该模式和对应 BFEP SDK 服务器参数，真实 PPCS 连接一次成功，约 2.97 秒，随后关闭返回 0，再次检查会话数为 0。SDK 初始化返回 0。此步骤未发送设备登录、视频或设备设置命令。

原 App 在测试前访问过设备设置，因此本次不能确认深睡后的独立唤醒。一次连接也不能证明持续稳定性。脱敏记录见 `docs/evidence/android-device-validation.json`；DID、账号、密码、令牌及截图均不进入 Git。

## 当前运行约束

- 配置的通道及连接模式可调整；命令通道 0、下载通道 4 来自静态证据，实际命令收发尚未验证。用户设备的私有配置已将 LTE 连接模式设为 94；通用模板仍保留原默认值。
- 下载若缺少开始/结束标记、长度不符或包序号不连续，会保留未完成文件而不标为可播放成品。
- SDK 文件可能仍包含厂商私有媒体结构；识别/解码失败时保留为“已下载未验证”，不会假定是 MP4。
- `recTime` 单位与设备时区尚未实际核对，因此索引保留原始时长值和设备本地日期。
- SDK 原生连接调用的内部超时尚未测量；主程序有桥接超时，手机停止时会请求中断并保留清理责任，不能保证立即终止失去响应的原生调用。
- API 任务目前只在内存记录，重启不自动恢复；初版仅支持单进程服务和串行摄像头任务。
- 用户的全天连续录像目标仍需确认设备 SD 工作模式，事件片段不能替代全天时间覆盖。

当前功能分支保留提交，不合并 main，等待最小真机闭环完成。
