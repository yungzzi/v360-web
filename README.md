# V360 Web

为自有 V360 Pro 摄像头提供私人网页监控：实时观看、现场声音、云台控制，以及自动保存和回放 SD 卡录像。界面采用浅色布局，兼顾电脑和手机。

已在一台太阳能供电的 4G 三画面设备和 Linux 云服务器上使用。当前仅适配已分析的 **V360 Pro 7.2.0 APK**，不保证其他型号或版本兼容；仍依赖厂商 PPCS 连接服务。已部署环境使用无手机后端，日常运行不需要 Android 手机、USB 或 ADB。

## 功能与限制

| 功能 | 当前行为 |
| --- | --- |
| 实时观看 | 主镜头可听现场声音；同一镜头最多三个观看窗口共享连接 |
| 三画面切换 | 主镜头、镜头二、镜头三切换；已有其他镜头观看者时提示冲突 |
| 电量与云台 | 电池图标和百分比；观看时每五分钟更新；主镜头支持方向点按 |
| 历史回放 | 按日期查看，拖动蓝线定位，空档只向后吸附到下一段录像 |
| 自动保存 | 服务器档每十分钟查询目录，提前下载、校验并生成网页版本 |
| 批次发布 | 可启用半小时批次：12:00–12:30 结束的录像在 13:00 发布已准备部分 |
| 录像管理 | 下载原片、锁定保留、失败清单和手动重试；网页可保存当前画面 |
| 访问保护 | 独立中文访问密码，可选记住登录十五天，退出及改密码可撤销会话 |
| 部署 | Docker Compose、HTTPS 反向代理、持久化目录、元数据备份及升级工具 |

只归档设备实际产生的观看期间和动作触发录像，不实现全天连续录像。两个附加画面只提供实时观看，不保存录像，也不包含双向对讲。

**不能保证全部录像都能取回。** 设备可能连接超时、拒绝下载或返回异常目录。失败会保留原因，达到自动尝试次数或发布时间后停止自动处理，可手动重试。发现数量、保存数量与可回放数量含义不同，不能据此宣称 SD 目录完整。

## 日常使用

在已部署的 HTTPS 地址登录，选择“实时观看”或“历史录像”。历史页优先展示已准备好、可直接读取服务器文件的录像；切换日期和拖动时间轴不应每次重新下载。同步状态、失败项和存储设置放在“管理与诊断”，详见 [历史回放](docs/recording-library.md)。

“停止观看”释放当前观看连接，“退出登录”撤销当前浏览器登录；两者都不会关闭服务器。后端继续自动保存。停止本地终端服务用 `Ctrl+C`；Docker 服务使用 `sudo docker compose stop v360`。

## 本地开发

开发环境为 Linux / WSL Ubuntu x86_64，Python 版本范围见 [pyproject.toml](pyproject.toml)。先安装 uv，然后在仓库根目录执行：

```bash
uv sync --extra dev --locked
uv run v360 --help
uv run v360 doctor
uv run --extra dev ruff check src tests tools
uv run --extra dev pytest -q
```

`doctor` 用于检查依赖；源码测试不代表真实摄像头验收。Node.js 可用于运行 `tests/*.cjs` 中的前端检查。

**只有源码不能直接连接摄像头。** 还需自行提供已支持的原 APK、私有 SDK/Android 运行依赖、ARM64 工作程序及自有设备配置。项目不分发原 APK、原厂 SDK 或已配置的通用设备凭据。

- [工具准备与构建](docs/build.md)
- [无手机后端及私有依赖](docs/native-backend.md)
- [通过正常账号导入自有设备参数](docs/account-onboarding.md)

已有完整私有配置的环境可启动：

```bash
uv run v360 serve --port 8080
```

浏览器访问 `http://127.0.0.1:8080`。初始网页登录使用本机 `.private/web.json` 的访问令牌；设置独立访问密码后使用新密码。不要把凭据发到聊天、截图、命令参数或 Git。具体见 [访问密码与恢复](docs/browser-password.md)。

本地默认轻量自动保存，不会直接采用服务器的大容量策略；准备部署目录时自动保存默认暂停。已有策略保存在数据库中，升级不会自动把所有环境改成同一档位。

## Docker 部署

应用镜像通过 Docker Hub 私有仓库 push/pull 分发；代码仓库公开不代表运行依赖或镜像也公开。现有部署采用单个后端进程，挂载数据目录，HTTPS 入口反向代理到回环端口，可部署在 `/v360/` 子路径。

```text
/srv/v360-web/
├── compose.yaml
├── compose.ops.yaml
├── .env
├── config/       # 设备配置、API 令牌，只读挂载
├── runtime/      # 私有运行依赖，只读挂载
├── data/         # SQLite、原片、网页版本，可写挂载
├── backups/      # 私有数据库和配置快照
└── tools/        # 宿主机升级工具
```

- `compose.yaml` 运行服务；`compose.ops.yaml` 是手动备份时显式启用的附加配置，不是第二个常驻后端。
- 容器限制为 **1 CPU、768 MiB 内存、无额外交换空间**；服务器档的原片、网页版本及直播缓存**合计最多 15 GiB**，另外保留至少 8 GiB 文件系统可用空间。
- 录像容量是上限，不是预先填满；默认保留期三十天，但空间不足会更早清理，不能保证保存十五个自然日。
- 多个浏览器可以访问；同一设备仍只运行一个后端实例，不同时运行新旧两个生产版本。

完整的构建、首次部署、备份、升级和恢复步骤见 [Docker 运维](docs/docker-deployment.md) 与 [资源预算](docs/resource-budget.md)。新机器仍需单独验证网络、设备兼容性和资源用量。

## 仓库与文档

`src/` 为后端与前端，`tools/` 为开发和部署工具，`android/` 为可选手机对照助手，`tests/` 为软件检查。`.private/`、`.tools/`、`data/`、`.env`、构建产物和原厂二进制均不应提交。

开发必须新建分支；检查通过后显式使用 `git merge --no-ff` 合并，普通提交不直接落在 `main`。运行 `python3 tools/setup_git.py` 可安装本仓库的 Git 规则。

[文档导航](docs/README.md) 区分当前使用说明和早期实验记录；[已知限制与后续方向](docs/next-features.md) 列出尚未解决的事项。历史验收数据只证明当时测试范围，不代表持续运行保证。
